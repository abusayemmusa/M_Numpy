========================================================
             GIT + GITHUB — MASTER CHEAT SHEET
========================================================

1. GIT BASICS
--------------------------------------------------------

Git
    Distributed Version Control System

Main Uses:

    Version Control
    Code Management
    Backup
    Collaboration
    Branching
    Merging
    History Tracking
    Team Development


========================================================
2. GITHUB
========================================================

GitHub
    Online platform for Git repositories.

Main Uses:

    Store Code
    Share Projects
    Collaboration
    Pull Requests
    Issues
    Code Review
    Open Source
    Project Management
    CI/CD


========================================================
3. GIT vs GITHUB
========================================================

Git:

    Software / Version Control System
    Runs locally
    Tracks code changes


GitHub:

    Online hosting/collaboration platform
    Hosts Git repositories
    Provides collaboration tools


========================================================
4. GIT INSTALLATION
========================================================

Check Git:

    git --version

Configure username:

    git config --global user.name "Your Name"

Configure email:

    git config --global user.email "you@example.com"

View configuration:

    git config --list

       ↓

       ↓

       ↓
   git commit
       ↓

       ↓
   git push
       ↓

6. CREATE REPOSITORY
========================================================

Create folder:

    mkdir my-project

Enter folder:

    cd my-project

    git init


========================================================
7. GIT STATUS
========================================================

Check current state:

    git status


Shows:

    Modified files
    Untracked files
    Staged files
    Current branch


========================================================
8. GIT ADD
========================================================

Add one file:

    git add main.py

Add multiple:

    git add file1.py file2.py

Add everything:

    git add .


Purpose:

    Move changes to staging area.


========================================================
9. GIT COMMIT
========================================================

Commit:

    git commit -m "Initial commit"


Good commit:

    git commit -m "Add KNN model"

Another:

    git commit -m "Fix data preprocessing"


========================================================
10. GIT LOG
========================================================

View history:

    git log

Compact:

    git log --oneline

Graph:

    git log --oneline --graph --all


========================================================
11. GIT DIFF
========================================================

View changes:

    git diff

Staged changes:

    git diff --staged


========================================================
12. GIT INIT
========================================================

    git init

Creates:

    .git/


.git contains Git repository metadata.

Do NOT normally edit it manually.


========================================================
13. GIT CLONE
========================================================

Clone repository:

    git clone REPOSITORY_URL

Example:

    git clone https://github.com/user/project.git


========================================================
14. REMOTE REPOSITORY
========================================================

View remotes:

    git remote -v

Add remote:

    git remote add origin REPOSITORY_URL

Change remote:

    git remote set-url origin REPOSITORY_URL


========================================================
15. GIT PUSH
========================================================

First push:

    git push -u origin main

Later:

    git push


Purpose:

    Local repository → GitHub


========================================================
16. GIT PULL
========================================================

    git pull

Purpose:

    GitHub → Local repository

Usually:

    fetch + merge/rebase


========================================================
17. GIT FETCH
========================================================

    git fetch

Downloads remote changes
without automatically merging them.


========================================================
18. GIT BRANCH
========================================================

List branches:

    git branch

Create branch:

    git branch feature-login

Switch:

    git switch feature-login

Create + switch:

    git switch -c feature-login


Older command:

    git checkout -b feature-login


========================================================
19. DELETE BRANCH
========================================================

Local:

    git branch -d feature-login

Force:

    git branch -D feature-login


Remote:

    git push origin --delete feature-login


========================================================
20. MERGE
========================================================

Switch to target branch:

    git switch main

Merge:

    git merge feature-login


Workflow:

    main
      ↓
    create branch
      ↓
    work
      ↓
    commit
      ↓
    merge into main


========================================================
21. MERGE CONFLICT
========================================================

Occurs when Git cannot automatically
combine changes.


Workflow:

    git status

Resolve conflict manually.

Then:

    git add .

    git commit


========================================================
22. REBASE
========================================================

    git rebase main

Purpose:

    Reapply commits on top of another base.


Merge:

    Creates merge history.


Rebase:

    Creates a more linear history.


Important:

    Avoid rebasing shared/public history
    unless you understand the consequences.


========================================================
23. GIT RESET
========================================================

Soft:

    git reset --soft HEAD~1

Mixed:

    git reset HEAD~1

Hard:

    git reset --hard HEAD~1


IMPORTANT:

    --hard can permanently discard
    uncommitted changes.


========================================================
24. GIT RESTORE
========================================================

Restore working-file changes:

    git restore file.py

Unstage:

    git restore --staged file.py


========================================================
25. GIT REVERT
========================================================

    git revert COMMIT_ID


Creates a new commit that reverses
an earlier commit.

Useful for shared branches.


========================================================
26. GIT TAG
========================================================

Create:

    git tag v1.0.0

List:

    git tag

Push:

    git push origin v1.0.0

Push all tags:

    git push origin --tags


Used for:

    Releases
    Versions


========================================================
27. GIT STASH
========================================================

Temporarily save unfinished work:

    git stash

View:

    git stash list

Apply:

    git stash apply

Apply latest and remove stash:

    git stash pop

Delete:

    git stash drop

32. GIT CHERRY-PICK

48. SSH
========================================================

    ssh -T git@github.com

    git@github.com:user/project.git

with GitHub repositories.

55. GIT BEST PRACTICES

3. Create branches for features.

7. Use .gitignore.

9. Write a good README.

10. Keep repository organized.

    =
    !=
    <>
    >
    <
    >=
    <=

18. AND
========================================================

========================================================

========================================================

22. IN
========================================================

========================================================
23. NOT IN
========================================================

SELECT *
FROM students
WHERE department NOT IN ('CSE', 'EEE');


========================================================
24. LIKE
========================================================

SELECT *
FROM students
WHERE name LIKE 'A%';


Patterns:

    %   → any number of characters
    _   → one character


Examples:

'A%'
'%a'
'_a%'
'%rah%'


========================================================
25. IS NULL
========================================================

SELECT *
FROM students
WHERE age IS NULL;


NOT NULL:

SELECT *
FROM students
WHERE age IS NOT NULL;


========================================================
26. ORDER BY
========================================================

Ascending:

SELECT *
FROM students
ORDER BY age ASC;


Descending:

SELECT *
FROM students
ORDER BY age DESC;


========================================================
27. LIMIT / FETCH
========================================================

Example:

SELECT *
FROM students
LIMIT 5;


Standard SQL/database-specific alternatives
may use FETCH FIRST / TOP.


========================================================
28. ALIAS
========================================================

    name AS student_name,
    age AS student_age

Table alias:

SELECT s.name
FROM students AS s;


========================================================
29. UPDATE
========================================================

UPDATE students
SET age = 21
WHERE id = 1;


IMPORTANT:

Always use an appropriate WHERE condition
unless you intentionally want to update every row.


========================================================
30. DELETE
========================================================

DELETE FROM students
WHERE id = 1;


Without WHERE:

DELETE FROM students;


Deletes all rows.

31. TRUNCATE
========================================================

TRUNCATE TABLE students;


Removes table data while retaining
the table structure.

Exact transactional behavior depends
on the database system.


========================================================
32. DROP
========================================================

DROP TABLE students;


Removes the table itself.

========================================================
49. JOINS
========================================================

Main types:

    INNER JOIN
    LEFT JOIN
    RIGHT JOIN
    FULL OUTER JOIN
    CROSS JOIN


Some DBMSs do not support every join
type identically.


========================================================
50. INNER JOIN
========================================================

SELECT
    s.name,
    o.order_id
FROM students s
INNER JOIN orders o
    ON s.id = o.student_id;


Returns matching rows.


========================================================
51. LEFT JOIN
========================================================

SELECT
    s.name,
    o.order_id
FROM students s
LEFT JOIN orders o
    ON s.id = o.student_id;


Returns all rows from left table
and matching rows from right table.


========================================================
52. RIGHT JOIN
========================================================

SELECT
    s.name,
    o.order_id
FROM students s
RIGHT JOIN orders o
    ON s.id = o.student_id;


Returns all rows from right table
and matching rows from left table.


========================================================
53. FULL OUTER JOIN
========================================================

SELECT *
FROM students s
FULL OUTER JOIN orders o
ON s.id = o.student_id;


Returns matching + nonmatching rows
from both sides.

Support varies by DBMS.


========================================================
54. CROSS JOIN
========================================================

SELECT *
FROM students
CROSS JOIN courses;


Produces Cartesian product.


========================================================
55. SELF JOIN
========================================================

A table joins with itself.

Example:

SELECT
    e.name AS employee,
    m.name AS manager
FROM employees e
JOIN employees m
ON e.manager_id = m.id;


========================================================
56. SUBQUERY
========================================================

SELECT *
FROM employees
WHERE salary > (
    SELECT AVG(salary)
    FROM employees
);


Query inside another query.


========================================================
57. CORRELATED SUBQUERY
========================================================

A subquery references the
outer query.


Example concept:

SELECT e1.name
FROM employees e1
WHERE e1.salary >
(
    SELECT AVG(e2.salary)
    FROM employees e2
    WHERE e2.department = e1.department
);


========================================================
58. CTE
========================================================

CTE = Common Table Expression


WITH high_salary AS (
    SELECT *
    FROM employees
    WHERE salary > 50000
)
SELECT *
FROM high_salary;


========================================================
59. RECURSIVE CTE
========================================================

WITH RECURSIVE hierarchy AS (
    ...
)
SELECT *
FROM hierarchy;


Useful for:

    Hierarchies
    Trees
    Graph-like relationships


Syntax varies somewhat by DBMS.


========================================================
60. SET OPERATIONS
========================================================

UNION
UNION ALL
INTERSECT
EXCEPT


Example:

SELECT name FROM students
UNION
SELECT name FROM teachers;


========================================================
61. UNION vs UNION ALL
========================================================

UNION:

    Removes duplicates.

UNION ALL:

    Keeps duplicates
    Usually faster.


========================================================
62. WINDOW FUNCTIONS
========================================================

Important:

    ROW_NUMBER()
    RANK()
    DENSE_RANK()
    NTILE()
    LAG()
    LEAD()
    FIRST_VALUE()
    LAST_VALUE()


Example:

SELECT
    name,
    salary,
    RANK() OVER (
        ORDER BY salary DESC
    ) AS rank
FROM employees;


========================================================
63. PARTITION BY
========================================================

SELECT
    name,
    department,
    salary,
    RANK() OVER (
        PARTITION BY department
        ORDER BY salary DESC
    ) AS dept_rank
FROM employees;


Ranks employees inside each department.
